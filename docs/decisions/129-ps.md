# `:ps`: the agents' processes

E16 of backlog #58: the agents' processes (first half) and what an
earlier run left (second half). The person's answers (2026-11-08): the
CPU and memory only in a `:ps` window; ending one ends the process
chosen, never the session, after checking again that it is under that
session; nothing is ended by itself. The leftovers are said at a start
(a count in a flash, like `:tidy`'s), listed in `:ps` under their own
heading, `a` all / `d` one after asking, `SIGTERM` then `SIGKILL`, never
by themselves.

What is read (`procs.rs`): `ps` twice, in the C locale on the system's
path, through `child::ask` (5 s, 64 KiB, its own group): first `-A -o
pid=,ppid=` (short whatever the machine runs: about 10 KiB for 900
processes, where every process's name alone passed 64 KiB), from which
each session's tree is taken (`under`: parents before children, at most
`MOST_UNDER` 200); then `-o pid=,ppid=,pcpu=,rss=,comm= -p LIST` for those
alone. A session whose process is not in the first listing is left out
(macOS's `ps` refuses a whole `-p` list for one number it does not take).
CPU is `ps`'s own `pcpu` (macOS: a decaying average; Linux: CPU time over
the process's life), in tenths of a percent of one core; memory is the
resident size. The name is `comm` without its directory.

Live (`live/procs.rs`): the sessions' processes are `Slot::Running`'s
pids; a look runs on a thread, one at a time (`Procs.looking`), its answer
taken in `Live::step`; a failure keeps what was read and says why. The
`:ps` window (`app/ps.rs`, `overlay::ps`) reads again every `PS_EVERY` 3 s
while open (`App::watch_ps` from `App::step`): per agent a line with the
sum, then its processes, the session's first and those under it indented;
`j k g G` move, `d` asks, `y` ends, any other key keeps, `esc` `q` close.

Ending (`procs::end`): refused for the session's own process
(`Refusal::Session`: `:forget` or a stop ends a session) and for imece's
relay (a program named as imece's own, right under the session:
`Refusal::Bus`), and for one no longer under the session
(`child::descends`, `Refusal::NotUnder`), checked just before the signal;
then `SIGTERM`, and `SIGKILL` after `KILL_GRACE` 2 s if it is still under
the session (checked again). Only that process: what it started itself is
its to end, or its parent's (a command run by Claude Code's shell tool
usually takes its children with it). A number freed and reused between the
check and the signal is the gap left (milliseconds); a reused number
after the grace is checked again. The journal says `Event::Killed { agent,
pid, name }` (`EntryKind::Person`), the agent's trace `ended by the
person: cargo (60321)`.

The demo (`Sim::look_procs`, `end_proc`): every started agent's session as
a made-up `claude` with `imece` under it, and while it works its
project's test program (a new number every `PROC_TICKS` 60); an ended one
stays gone (`Extras.ended`); refused as live refuses.

Read cost: two `ps` calls every 3 s while the window is open, nothing
while it is shut; memory: one list of the sessions' processes. Ten times
the agents is ten times the `-p` list (a few KiB). Migration: none
(memory only; the journal's event new). Failure: `ps` missing or slow is
said in the window (`the processes could not be read: …`).

## What an earlier run left

A run of imece that ended without ending its sessions (a crash, a
terminal closed, `kill -9`) leaves them running with what they started.
Recognised (`procs::leftovers`) by the command line: every session
imece starts names its worktrees directory (`<state>/worktrees/…`: the
notes directory of record 110, a worker's scratch and worktree), so
`pgrep -U <uid> -f` with that directory and a `/`, the path's ERE
characters escaped (`procs::literal`), finds them in a short answer
(the whole `ps -A -o args` passed 64 KiB). A process found is left over
(`left_roots`) when nothing above it (`above`: the parents from the `ps
-A -o pid=,ppid=` pairs, at most `MOST_UP` 64) is this imece (its
number, whatever it is named) or a program named as imece is
(`is_imece`; Linux cuts a name at 15 bytes, so a 15-byte name that
starts imece's counts), it is not one itself, and none above it is found
too (then it is in that one's tree). So another imece running now keeps
its own sessions, and a process the person started on a file there (an
editor) is listed: the person decides, nothing ends without a `y`. At
most `MOST_LEFT` 20 trees, each `under` its first; its heading the word
its command line names under the worktrees (`place_in`, from `ps -ww -o
args=`, cut at 80 characters, `?` when not read).

The look runs with the agents' one (`Live::look_procs`, on its thread,
one `Read` with both); `World.procs.left`. A start asks for it
(`App::start_ps` after `start_tidy`) and says the count once the look
answered (`said_left`, from `watch_ps` every step): after `:tidy`'s, its
flash joined with ` · ` when that flash is up, alone else, nothing when
the `:ps` window is open. In the window (`ps_rows` with `Whose::Agent` /
`Whose::Left`), `LEFT FROM AN EARLIER RUN · N` under the agents, each
tree as an agent's; `d` on one asks `end node (39100), left from an
earlier run?` (`Sure::One`), `a` all of them (`Sure::AllLeft`; none:
`nothing is left from an earlier run`), `y` ends (`procs::end_left`).
Ending checks again just before: the tree's first still found by the
`pgrep`, still with no imece above it (`still_left`, three calls for all
the trees asked), and each process it or under it (`in_trees`,
`child::descends`); then `SIGTERM`, and after `KILL_GRACE` the same
check and `SIGKILL`. A flash says how many (`you ended 3 processes left
from an earlier run`), none: `that is no longer left from an earlier
run`; nothing goes in the journal (no agent's: the flash, as `:tidy`'s
removals).

Gaps: a process under a tree whose first ended at the `SIGTERM` is no
longer under it at the `SIGKILL` (it went to init or a subreaper), so
one that ignores `SIGTERM` stays; and a command a crashed session
started whose session is already gone names no worktree on its command
line (it runs *in* one: a working directory, which `ps` does not show
cheaply), so it is not found. The demo (`Sim::left`, `Sim::end_left`):
a crashed run's `claude` with its relay and a test, and a `node` alone,
gone once ended, a tree with its first.

Cost: a `pgrep`, a `ps -A` and one `ps -p` more per look (only at a start
and while `:ps` is open), and one `ps -ww -o args=` per tree found.
